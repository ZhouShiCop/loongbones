# ADR-0002 原生格式容器方案

- 状态：**已定案**（负责人 2026-10-19）
- 日期：2026-10-19
- 关联：规范 §3.3（原生文件契约）、§4（向后兼容策略）

## 已定案（负责人 2026-10-19）

1. **当前阶段采用 JSON 作为核心工程数据格式，图片资源独立存储。**
2. **开发期使用目录工程**，支持**外部图片引用**与**工程内资源**两种方式。
3. 未来**可以**增加单文件打包，但**不得因此建立两套互不兼容的数据模型**。
4. **暂不引入 zstd 等压缩方案，也不提前实现二进制容器。**
5. **必须保留清晰的资源存取接口**，为未来扩展预留空间。
6. **当前 Task 2 的领域模型范围**：静态 Scene/Node、图片实例和 Atlas/Region 元数据；
   **Spine 骨骼动画数据、约束和其他高级附件不进入本 Task，也不进入当前核心 Schema。**

## 由此确定的技术形态

```
<project-dir>/
  project.json          ← 核心工程数据（JSON，人类可读、可 diff）
  assets/               ← 工程内资源（图片）
  ...                   ← 目录工程形态
```

- **核心数据 = JSON**，不压缩、不二进制化（Phase 0→1 范围内）
- **图片独立存储**，通过项目内的**资源存取接口**（`AssetStore` 抽象）访问，
  接口需同时支持"外部引用"与"工程内资源"两种后端
- 单文件打包（未来）= 同一套模型的**另一种容器实现**，不是新模型
  ⇒ 序列化层必须与领域模型解耦，规范 §3.1 已要求"内部交换使用与文件同一 canonical schema/codec"

## 仍然生效的规范硬性要求（不属于待决项）

来自规范 §3.3，作为 Schema RFC 的前置约束直接执行：

- 必需元数据：`formatId`、`formatVersion`、`minimumReaderVersion`、`projectId`、
  对象稳定 ID、资源清单、单位/时基、扩展命名空间、可选内容校验和
- 核心字段有明确类型/默认值；**未知字段必须 round-trip 保留**
- 旧 Reader 遇未知**必需**能力 → **明确报错**，不得"打开后保存并悄悄删掉"
- 保存：临时文件 → 完整写入/校验 → **原子替换**；损坏或迁移失败保留原文件并给出可定位诊断
- 内部模块交换使用与文件同一 codec；**不得为各模块再造一套语义不同的 JSON 中间格式**

来自规范 §4：区分 `formatVersion`（持久化契约）与 `appVersion`（应用发布版）；
优先只增不改；每次 schema 变更附迁移函数 + 旧版本 fixture + 迁移前后语义比较。

## 对 Task 1（Core Asset Model）的直接约束

Task 1 **不实现** JSON 序列化（其 §2.2 明确禁止），但必须满足：

| 约束 | 落实方式 |
|---|---|
| 模型可被后续序列化模块完整读取 | 数据结构用**纯值类型 + 显式集合**，不藏不可导出的内部状态 |
| 不把 Qt / 文件句柄 / GUI 状态放入 Project | Task 1 §3.1 已要求；本 ADR 追加：**不引入任何序列化库依赖**（Task 1 §6） |
| 为资源存取预留接口 | `ImageAsset` 只存**元数据 + 存储模式 + 位置标识**，不解析路径、不读文件（Task 1 §3.5） |
| 路径越界防护（规范 §8.2） | 路径规范化与"落在资源根内"的校验属后续模块，但接口形状本阶段定下 |

## 未定（后续阶段，不阻塞当前）

- 压缩：是否需要、何时引入（依赖目标工程规模，需负责人给出预期）。
- 单文件打包的具体容器（zip？自定义？），以及是否引入体积优化。
- 二进制重负载段：ADR-0003 的契约若长期稳定，可为将来的二进制编码预留字段类型与对齐规则，
  但**现在不实现**。
- 扩展包是否首版落地，还是先只做"命名空间 + 忽略未知"的最小集。
