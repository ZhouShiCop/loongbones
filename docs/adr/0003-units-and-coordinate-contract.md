## C1 几何坐标系 ✅ 已定案

**契约：Y-up。** 作为正式约定写入 schema 与文档。

理由：行为对齐目标是 Spine（Y-up），可减少导入/导出时的符号折算层数；
UI 层的 Y 翻转集中在 render adapter 一处（规范 §3.1 的依赖方向）。

**验证**：golden skeleton 的骨骼世界矩阵逐元素值锁定；
Domain 与 Render 两侧不得各自翻转。

## C2 角度单位 ✅ 随 C1 定案

**契约：存储与接口用度（`rotationDeg`），内部求值用弧度，边界集中转换。**

- 规范 §10.1 要求单位进字段名
- 旋转正方向与 C1 绑定（Y-up 下逆时针为正）
- 禁止在 GUI 与求值器中散落魔法数（规范 §8.3）

**验证**：golden 值 + 90°/180° 往返用例。

## C9 矩阵布局与组合顺序 ✅ 随 C1 定案

**契约：2×3 仿射、行主、`world = parent × local`。**

与 Spine 一致。禁止各模块自行假设（规范 §8.3）。
**验证**：golden 世界矩阵逐元素。

## C5b UV 的 V 方向 🔬 待验证（本 ADR 的首要待办）

**状态：负责人明确指示——暂不拍板，必须通过真实样本与可复现的验证程序确定，
不允许根据经验直接假设。**

背景：Spine/OpenGL 惯例 V 向上，而图像文件与多数 2D 管线 V 向下。
这个方向的取值错误会导致贴图**上下翻转**，且在纯色/对称图上看不出来。

必须满足的条件（负责人要求"真实样本 + 可复现验证程序"）：

1. **用真实语料**：语料中 `orig`/`offset` 与 `size` **不一致**的 region
   （即存在裁剪 trim），其裁剪区域在图像上的实际上下位置可作为判据；
   另用**上下不对称**的 region（不能选上下对称的图，否则两种约定渲染一致、无法区分）。
   > ⚠️ Phase 0 实测：**sdorica 语料 0% 裁剪**（`offset` 全 0、`size == orig`），
   > 因此判据 1 在该语料上**不可用**，需另找判据（见 §待验证计划）。
2. **验证程序必须可复现**：列入 `tools/`，输出数值而非"看起来对"，登记进 `STRUCTURE.md`。
3. **不得用历史 Canvas 解释器的产出作为判据**——旧项目的渲染链已被判定不可信
   （CanvasRenderer 对 mesh 支持残缺，见 `.workbuddy` 记录）。

**产出**：ADR 更新 + 该契约项标记"已验证"，附验证程序路径与结论数据。

## C6 动画时基 ⏸ 当前阶段不涉及

**负责人决定：当前资产组合器第一阶段不涉及动画，因此不作为当前开工阻塞项。**

进入动画模块前**必须**依据真实样本确定：
- 时基（整数 tick vs 浮点秒）
- 帧率来源（Spine 3.2.01 二进制头**没有** fps 字段；旧项目写死 30 是**未经验证的假设**）
- 换算规则（有理数 / 明确舍入）

**不得沿用未经验证的固定 30 FPS 假设。** 这条记入风险项，不得遗忘。

## C3 骨骼帧值域 ⏸ 当前阶段不涉及

已确认结论（进入动画模块时直接采用，无需重新调查）：
Spine 骨骼动画帧是**相对 setup 的增量**，不是绝对值。
旧项目第一版按绝对值减 setup，导致 `mecha/idle/root` 差 90°。
若采纳增量，字段名应体现（如 `rotateOffsetDeg`）。

## C4 非加权 mesh 顶点空间 ⏸ 当前阶段不涉及

已确认结论：Spine 非加权 mesh 顶点是**槽骨骼局部坐标**（DragonBones 是骨架空间绝对坐标）。
旧项目因此出现"动画一播就散"。统一采用槽骨骼局部，由求值器算世界坐标。

## C5a mesh UV = region 相对坐标 ⏸ 当前阶段不涉及

已确认结论：Spine 文件里 mesh 的 `uvs` 就是 **regionUVs（region 内相对 [0,1]）**；
整页归一化 UV 是 runtime `UpdateUVs()` 加载时才算的。
把文件 UV 当整页坐标再逆变换 = 双重变换，UV 被拉出 [0,1]（旧项目 task_F1 的根因）。

## C7 曲线插值 ⏸ 当前阶段不涉及

Spine 支持线性 / stepped / 贝塞尔（4 点），二进制还可能出现"曲线采样点"形态。
进动画模块前统计采样点形态的语料出现率再定支持等级。

## C8 颜色 / 透明度 📋 契约记录

Spine 颜色为 0..1 浮点 rgba。规范 §8.3 要求范围进 schema。
**契约：0..1 浮点**，并明确混合模式含义，避免与 0..255 整数混用。

## 当前阶段（Task 1）实际生效的契约

Task 1 只做图片/图层/简单组合，因此**此刻真正生效的只有 C1、C2、C9、C8**：

| 契约 | 在 Task 1 的体现 |
|---|---|
| C1 Y-up | `Transform` 的 `y` 语义为 Y 向上（不是屏幕坐标的 Y 向下） |
| C2 度 | `Transform::rotationDeg`，默认值 0 |
| C9 2×3 行主、`parent × local` | `Transform` 只存**局部** TRS，不含世界矩阵；组合顺序在此固定 |
| C8 0..1 浮点 | Task 1 无颜色字段，但不得引入 0..255 |

> **注意**：Task 1 §3.6 的 `Transform` 只要求 `x/y/rotation/scale_x/scale_y`，
> **不实现矩阵、锚点、斜切**（其 §3.6 明确"本任务不实现复杂变换矩阵、锚点、斜切或完整渲染计算"）。
> 因此 C9 在 Task 1 表现为"字段语义与组合顺序的口头约定 + 文档"，不落成矩阵代码。
