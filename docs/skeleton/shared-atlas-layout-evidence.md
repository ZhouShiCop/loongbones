## 2. 命名规则（A1 的关键结论 —— 不得写死猜测）

计划 §2 已提示「与目录同名」只是**近似描述**，实际形态由本取证确定：

- 目录名是 `watch`，图集名却是 **`h0164s5_watch`**
  = **上级目录名 `h0164s5` + `_` + 目录名 `watch`**。
- 全量枚举里**没有**出现严格 `basename(dir) + ".atlas.txt"` 的形态（0 例）。

⇒ 因此**不能用「与目录同名」作为规则名**（会误导）；
本任务涉及的真实形态是「**`<上级目录名>_<目录名>.atlas.txt`**」，
且它在语料里**只有 1 处、2 个单位**。规则如何泛化属 A2 提案范围，本取证只负责给出事实。

## 6. A3：共享资源的资产语义（**已定案 → D53**）

D40 已定案「共享图集**复用同一份 Atlas / Texture 资产**，指向同文件」，但留有
「具体对象可选**共用**还是**独立化**」⇒ 本节给出推荐与理由。
**负责人 2026-10-24 已认可该推荐，落为 `DECISIONS.md` D53。**

**结论：共用同一份 Atlas / TextureAsset 对象**（不是每个骨架各建一份副本）。

| 理由 | 说明 |
|---|---|
| 与 D40 一致 | D40 的核心就是"指向同文件"；若各建副本，则两个 Atlas 指向同一文件却是两个对象，下次导入/重开时容易出现"两份资产、一个文件"的歧义 |
| 与 D25 **不冲突** | D25 是「**同一单位重复导入**默认创建副本」；本场景是「**两个不同单位**引用同一份源资产」，语义不同 ⇒ D25 不适用，不是它的例外 |
| 资源不冗余 | 同一张 `h0164s5_watch.png` 若被两个骨架各暂存一份，工程里会出现两个 `TextureAsset` 指向同一份字节，重开后计数与去重规则（B6 §3.1 纹理名去重）都要额外兜底 |
| 重开一致性易证 | 共用 ⇒ 落盘只有 1 份 Atlas + 1 份 Texture，重开后仍是 1 份；B5 的逐项比对（`[deep-compare]`）只需覆盖"两个骨架都引用同一 Atlas ID"这一条 |

**阶段 B 必须验证的点（D53）**：

1. 两个骨架导入后 `Skeleton.atlasIds` 都指向**同一个** `Atlas.id`；
2. 工程内 `atlases` / `textures` 各只有 **1** 份；
3. `draft.resources` 的暂存清单对同一 PNG **不重复**（B6 §3.1 的纹理名去重保持不变）；
4. **同一源文件被两个骨架引用时，不得各自新建 `Atlas.id`**
   —— **对象 ID 唯一**与**源文件路径相同**是两件事，不能混（复核新增项）。
