# TASK 1：实现核心资产数据模型（Core Asset Model）

状态：`READY_FOR_REVIEW`（独立重新构建并验证 42/42 用例通过；待负责人最终验收）

## 1. 任务目标

建立 Asset Composer 的核心数据模型，为后续 JSON 工程格式、资产管理、组合器 GUI 和单文件打包提供统一的数据基础。

本任务只负责定义和实现内存中的业务数据结构及其基本操作，不负责工程文件读写，也不负责 GUI。

核心目标：

1. 支持图片节点、分组节点及其层级组合关系。
2. 支持图片资源与图片节点分离，同一图片资源可被多个节点引用。
3. 支持节点变换、可见性及稳定的唯一标识。
4. 保证节点层级和资源引用关系合法。
5. 建立独立于 Qt 的核心模块和自动化测试。

## 2. 范围约束

### 2.1 本任务必须实现

- Project：工程数据容器。
- Node：节点基础模型。
- GroupNode：分组节点。
- ImageNode：图片节点。
- ImageAsset：图片资源元数据。
- Transform：二维变换数据。
- 节点层级关系管理。
- 资源引用关系管理。
- 基础数据合法性校验。
- 核心数据模型单元测试。

### 2.2 本任务禁止实现

- JSON 序列化与反序列化。
- 工程文件保存、加载及版本迁移。
- Qt 窗口、控件或画布。
- 图片解码、渲染及缩略图。
- 外部资源路径解析与资源打包。
- Spine、DragonBones、骨架、蒙皮及动画系统。
- 完整撤销重做系统。
- 未经需求确认的插件系统或复杂继承框架。

允许为后续模块预留必要的接口，但不得提前实现这些模块。

## 3. 核心数据结构

### 3.1 Project

工程数据的顶层容器。

建议包含：

- 稳定的工程 ID。
- 工程名称。
- 根节点 ID。
- 节点集合。
- 图片资源集合。

要求：

- Project 是节点和资源数据的权威所有者。
- 节点与资源通过稳定 ID 关联。
- 不将 Qt 对象、文件句柄或 GUI 状态放入 Project。
- 工程集合应能够被后续序列化模块完整读取。

### 3.2 Node

所有组合节点的公共数据。

建议包含：

- 稳定且唯一的节点 ID。
- 节点名称。
- 节点类型。
- 父节点 ID。
- 子节点 ID 的有序列表。
- 局部变换。
- 可见性。

要求：

- 节点 ID 不依赖名称或集合索引。
- 子节点顺序具有明确语义，并用于定义同一分组中的绘制顺序。
- 不允许节点同时属于多个父节点。
- 不允许形成循环引用。
- 根节点不得作为普通子节点重复挂载。

### 3.3 GroupNode

表示逻辑分组。

要求：

- 可以包含其他 GroupNode。
- 可以包含 ImageNode。
- GroupNode 是普通节点容器；其他普通节点（包括 ImageNode）同样可以包含子节点，父子关系不按渲染类型限制。
- 支持嵌套分组。
- 自身不直接引用图片资源。
- 子节点顺序稳定。

### 3.4 ImageNode

表示组合场景中的一个图片实例。

建议包含：

- 公共节点数据。
- ImageAsset ID。

要求：

- 不直接持有图片二进制数据。
- 不复制 ImageAsset 的权威元数据。
- 同一个 ImageAsset 可以被多个 ImageNode 引用。
- 每个 ImageNode 拥有独立的局部变换与可见性。
- ImageNode 可以作为普通父节点容纳子节点；子树绘制顺序由父节点的有序 children 及统一绘制规则决定。

### 3.5 ImageAsset

表示图片资源的逻辑身份，而非图片在组合中的实例。

建议包含：

- 稳定的资源 ID。
- 资源名称。
- 资源类型。
- 存储模式。
- 资源位置标识。
- 可选的像素宽度与高度。

存储模式至少为后续外部引用和工程内资源两种方式保留明确的枚举值。

本任务不负责解析路径、读取图片或校验文件是否存在。

### 3.6 Transform

使用二维变换模型。

建议包含：

- x、y：局部位置。
- rotation：旋转角度。
- scale_x、scale_y：横纵缩放。

要求：

- 统一角度单位，建议使用度。
- 初始缩放默认为 1。
- 初始旋转和位置默认为 0。
- 明确坐标系约定，并形成文档。
- 本任务不实现复杂变换矩阵、锚点、斜切或完整渲染计算。

## 4. 数据一致性规则

核心模型必须提供统一的合法性校验机制。

至少验证：

1. 工程 ID、节点 ID 和资源 ID 均有效且唯一。
2. 根节点存在，且类型为 GroupNode。
3. 除根节点外，每个节点恰好属于一个父节点。
4. 父子关系双向一致。
5. 不存在循环层级。
6. ImageNode 引用的 ImageAsset 必须存在。
7. GroupNode 不允许直接引用 ImageAsset。
8. 不允许删除仍被其他节点引用的节点或资源而留下悬空引用。
9. 节点类型与实际数据结构一致；普通节点类型均允许挂载普通子节点。
10. 数值型变换字段必须是有效的有限数值，不接受 NaN 或无穷值。

唯一根节点必须是 GroupNode、无父节点且不可移动或删除；除此以外，不得因节点类型拒绝合法的父子关系。该规则取代此前 Back_task 中“图片节点不能包含子节点”的临时验收约束，Task 2 负责把实现与测试统一到本契约。

校验失败时应提供可定位的错误信息，而不是静默修正或忽略问题。

## 5. 基本操作接口

根据实际代码语言和项目规范实现等价接口，至少包括：

- 创建工程。
- 创建分组节点。
- 创建图片节点。
- 创建图片资源记录。
- 重命名节点。
- 设置节点变换。
- 设置节点可见性。
- 将节点移动至另一普通节点。
- 调整同一分组内的节点顺序。
- 查询节点及其父子关系。
- 查询图片资源及其引用节点。
- 删除节点。
- 删除未被引用的图片资源。
- 校验整个工程的数据一致性。

所有会修改工程的操作必须经过核心模型提供的统一入口，不允许调用方直接修改内部集合后破坏数据约束。

删除节点时，必须明确其子节点的处理策略；删除分组不得隐式丢失子树。若操作存在歧义，应要求调用方显式指定策略。

## 6. 架构要求

- 核心模块不得依赖 Qt。
- 核心模块不得依赖具体 JSON 库。
- 核心数据结构不得依赖 GUI 控件。
- 资源路径解析与文件系统操作属于后续 Asset 模块。
- 所有公共操作均应有明确的参数、结果及错误处理约定。
- 不得为未来功能引入当前不需要的抽象层。
- 采用项目现有语言、构建系统和代码风格，不擅自更换技术栈。

## 7. 测试要求

必须建立自动化单元测试，覆盖：

- 创建空工程及根节点。
- 创建与嵌套分组。
- 创建图片资源和图片节点。
- 多个图片节点引用同一资源。
- 节点移动与顺序调整。
- 节点变换和可见性修改。
- 重复 ID 检测。
- 不存在的父节点与资源引用检测。
- 多父节点检测。
- 循环层级检测。
- 删除节点及删除资源的引用保护。
- 非有限变换数值检测。
- 错误操作不得造成部分修改或不一致状态。

涉及多步骤的数据修改时，应保证操作成功后数据一致；操作失败时，不得留下半完成状态。
