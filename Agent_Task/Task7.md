## 5. 渲染与图形库选型（**D43**：阶段 A 必须定案）

### 5.1 硬约束（来自需求，不是偏好）

1. **必须能画带 UV 的纹理网格** —— mesh / weightedMesh 是核心资产（语料 2,979 + 17,271），
   逐顶点 UV 的三角网格是刚需。
2. 需要**逐附件 tint / alpha** 与**混合模式**（Spine 的 normal / additive / multiply / screen；
   本项目 Reader 对未知混合模式是**拒绝**的 ⇒ 后端必须能表达这些模式）。
3. 视口需随动画**逐帧更新**（mesh 顶点在 deform / 蒙皮后会变）。
4. 经 **Render Adapter** 隔离，**不得**把后端 API 渗进 Domain / Runtime。
5. **Qt 版本不绑定**（负责人 2026-10-24）⇒ 不得选用**仅某一 Qt 版本可用**的后端（如仅 Qt 6 的 QRhi）。
6. **界面可能继续优化** ⇒ UI 承载方式可变，渲染后端必须**可替换**，且不得因 UI 改动牵连渲染层。
7. **平台优先级：Windows > macOS > Linux**；**性能基线：AMD 核显（集显）可流畅使用即可** —— 2D 骨架渲染负载不高，
   重点不是峰值性能，而是**三平台都能跑、且 driver 兼容面够宽**。

### 5.2 候选与推荐

| 候选 | 评价 |
|---|---|
| **⭐ QOpenGLWidget（承载）+ 自研 OpenGL core（Win/Linux 3.3、macOS 4.1）2D 渲染器** | **推荐**（在「Qt 版本不绑定」前提下）。`QOpenGLWidget` **Qt 5 / Qt 6 都有** ⇒ 不绑 Qt 版本；**无第三方渲染依赖**；自研薄层可完全掌控自定义顶点/索引与着色器 ⇒ 带 UV 的纹理网格、tint/alpha、混合模式都能精确表达；**AMD 核显跑 2D 骨架绰绰有余**。**代价**：macOS 上 OpenGL 已被 Apple 标记弃用（仍可用到 4.1）⇒ 属长期风险，靠 Render Adapter 预留后端替换 |
| bgfx（第三方） | **已裁定接受，但作为「后期单独发行版本」（D51）**：一套代码拿 D3D11/12、Metal、Vulkan、GL，**天然解决 macOS Metal**；体积小、2D/3D 皆宜、核显无压力。**代价**：第三方 C++ 依赖与构建复杂度 ⇒ 因此**不进一期**，仅作后期可选后端变体 |
| Qt 6 + QRhi | **本轮不选**：后端无关、官方维护是其优点，但 **QRhi 属 Qt 6** ⇒ 与「Qt 版本不绑定」冲突；若日后确定只用 Qt 6，可重新上位 |
| Qt Quick Scene Graph（QSG） | **QML 已采用（D50）**，但**视口不走 QSG 材质路径**：推荐 `QQuickFramebufferObject`（Qt 5 / 6 均有）承载自研渲染器（见 §5.5）；仅在日后要深度融入 QSG 合成时，才考虑写 `QSGMaterialShader` |
| Skia | 2D 能力强，但偏位图 / 矢量，**带 UV 的网格渲染不如直接用 GL/Vulkan 直接**、且依赖较重 |
| QPainter / QGraphicsView | **排除**。无法做**带 UV 的纹理网格**（只能画仿射变换的位图），而 mesh 是核心资产 |

### 5.3 QML 是什么（负责人要求解释）

**QML**（Qt Meta / Modeling Language）是 Qt 的**声明式 UI 语言**，配合 **Qt Quick** 运行时使用：

- 用接近 JSON 的声明式语法描述界面与交互（而不是 C++ 手写控件），**天然支持动画、过渡、状态机**；
- 渲染走 **Qt Quick Scene Graph**（GPU 合成的场景图），适合流畅、带动效的现代化界面；
- 它与传统的 **Qt Widgets**（C++ 控件）是**两套并行的 UI 技术**，可混用，但通常二选一。

**对本项目的意义**：

- ✅ 好处：时间轴、曲线编辑器、属性面板、视口叠加层这类 UI 用 QML 写起来更快、动效更好；
- ⚠️ 代价：引入 QML/JS 层与 Qt Quick 依赖；视口若走 QSG，自定义混合模式要写 `QSGMaterialShader`；
- ⚠️ 与「**界面可能继续优化**」叠加 ⇒ 更应把**渲染后端**经 Render Adapter 隔离，避免 UI 技术更替牵连渲染层；
- ⚠️ 与「**Qt 版本不绑定**」的关系：Qt Quick / QSG 在 Qt 5、Qt 6 都有，但 Qt 6 的 QRhi 化让 QSG 后端与 Qt 版本耦合更紧。

### 5.4 QML 的影响边界（**已裁定采用 → D50**）

**结论**（负责人 2026-10-24）：**采用 QML**，用于**界面承载**（时间轴、曲线编辑器、属性面板、视口叠加层等）。

但它**不改变**渲染选型，只改变**视口如何被嵌进界面**：

| 层 | 由谁决定 |
|---|---|
| 界面（面板 / 时间轴 / 曲线编辑器 / 叠加层） | **QML / Qt Quick**（D50） |
| 视口在界面中的承载 | 推荐 `QQuickFramebufferObject`（Qt 5 / Qt 6 都有 ⇒ 不绑版本） |
| **用什么图形 API 画网格** | **Render Adapter 之后的后端**（一期自研 OpenGL core） |

⇒ QML 与渲染后端**解耦**：日后若 UI 从 QML 换回 Widgets（「界面可能继续优化」），
只换承载件，**渲染后端不动**。

## 8. 量级与风险

- **量级远大于 Task 5**：Task 5 阶段 B 为产品 1,400–2,000 行 + 测试 1,400–1,800 行、5–7 个实现会话；
  Task 7 仅 `timelines` 就有近 500 万条语料，预计**数倍于此**，且需新的取证工具。
- **取证工具**：需新增时间线普查探针（参照 `tools/skeleton-probe/` 既有做法：只读语料、只产出统计）。
- **格式升 v4**：迁移链 v3 → v4 必须**纯函数**（不生成 ID、不改既有字段、不碰磁盘、幂等），
  写出统一为 v4；v1 / v2 / v3 Reader 对 v4 的行为需按 D29 模式固定（拒绝、不降级、不静默丢字段）。
- **曲线取值风险**：bezier 求解与手柄语义若与 Spine 不一致，会直接违背「对齐 Spine」目标
